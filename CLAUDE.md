## Правила бизнеса
1. **Один формат для всех бутиков.** Не делай «особых» постов, не обещай никому особых условий, не прячь число подписчиков только у части бутиков. Никто не платил больше других.
2. **Не обещаем «закреп»** (pin). Говорим просто: «можем вас добавить».
3. **Просьба выложить сторис — только после того, как пост уже в канале.** Прямо, с готовой картинкой (`story_sauda.png`), без «если захотите». Первое сообщение бутику сторис не просит.
4. Любой бутик может попросить убрать пост — убираем сразу.
5. **Видео:** призыв в конце («подпишись», «ссылка в шапке» и т. п.) **для каждого видео разный**: добавляй его только когда владелец сам назвал фразу для этого видео; если не сказал, не добавляй (решение 25.10.2026). В силе: только настоящие бренд-ассеты (логотип, шапка канала, реальные записи экрана бота), никаких придуманных ИИ экранов, ИИ-контент помечать.
6. В канал публикуем **только Алматы**. Посты из других городов блокируются.
7. Теги и категории: правила хэштегов решены владельцем (аудитория ≤2 отдельно, топ-5 одежды, `#Семейнаяодежда`, `#Домашняяодежда`, «т.б.» при 10+ категориях). Подробности в памяти `sauda-hashtag-selection`. Не пересматривай.
8. Админка «**import-first**»: вручную бутики не вводятся, только URL Instagram. Не строй новые CRUD-страницы и не улучшай Dashboard/Settings без явной просьбы. Никаких фейковых/seed-данных.
9. Монетизация **не решена**. Цены бутикам не называем, пока владелец не решит.
10. Голоса и музыка: проверяй лицензию. Казахский голос Piper (`kk_KZ-issai`) — CC BY 4.0, нужна подпись-кредит.
11. В текстах для людей: без «без рекламы» и «я как пользуюсь», без роли постороннего, честно про «фильтра по размеру и цвету нет»; ссылка лучше во втором посте ветки.

## Как принимать критичные решения
Для решения, которое трудно отменить, стоит денег или касается репутации перед бутиками:
1. Сформулируй решение одной фразой и скажи, что необратимо, а что нет.
2. Дай 2–3 варианта, с реальными цифрами владельца. Где цифр нет, пиши «не известно».
3. Раздели: **факт** (проверено) / **допущение** / **моё мнение**.
4. Дай рекомендацию, степень уверенности и условие, при котором она изменится.
5. Для важного прогони через `startup-strategist`, затем через `devils-advocate`. Их выводы показывай владельцу без смягчения.
6. «Панели покупателей», «советники» и прочие симуляции — гипотезы, а не рыночные данные. Предлагай дешёвый реальный тест.
7. Решают владелец и его команда. Ты даёшь аргументы, риски и числа.

## Как работать в этом репозитории
- Стек: Next.js 15 (App Router) + TypeScript, Tailwind v3, Supabase Auth, Prisma + Postgres, TanStack Query, Zod, Vitest. Проверка: `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`.
- **БД и сеть:** песочница Bash не достаёт до Supabase. Скрипты с доступом к БД запускаются через панель Terminal: `node --env-file=.env node_modules/vite-node/vite-node.mjs --config vitest.config.ts <script>`. `.env` указывает на **боевую** базу: перед записью покажи, что изменится, и делай бэкап, как в `scripts/backfill-hashtags.mts`.
- Публикация конкретного бутика: скрипт по образцу `publish-handles.ts` (Publish Queue берёт только самый старый).
- В рабочем дереве лежит **неоформленная работа над Threads** из другой сессии: не коммить её вместе со своими правками. Перед коммитом смотри `git status`.
- Не делай лишнего: правка = то, что просили. Не добавляй заглушки и фиктивные данные.
